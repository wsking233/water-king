# 大水之王 · Water King

项目重新开始。当前仓库仅保留本说明，尚未实现新原型。

## 第一阶段目标

做一个在浏览器中可操作、可验证的前端单机原型，验证核心记录流程是否方便、反馈是否清晰。以现有的饮水与如厕记录主题为起点，具体交互和视觉设计重新设计。

原型需要形成完整操作闭环，不能只展示静态页面：新增记录、查看结果、撤销误操作，刷新后仍能看到本地记录。

## 范围

- 饮水记录：录入饮水量，查看今日累计。
- 如厕记录：记录小便或大便，查看今日次数。
- 今日明细：查看记录及时间，支持撤销误操作。
- 本地保存：数据保存在当前浏览器，可清空并重新体验。
- 排行榜：如需验证榜单界面，使用明确标注的模拟数据，不实现跨用户排名或上传。

不做账号、登录、服务端、云同步。真实多人排行榜是唯一已知可能需要服务端的功能，本阶段不接入，也不提前设计其服务架构。暂不考虑发布部署、平台适配和未来扩展。

## 技术方案

采用 Vite + React + TypeScript 的单个前端项目，普通 CSS 完成样式，通过浏览器本地预览。

数据流保持简单：用户操作 → 前端状态更新 → 本地存储 → 界面反馈。统计直接由本地记录计算；使用 localStorage 保存少量原型数据，按设备本地日期计算“今日”。保存失败时明确提示，不能显示虚假的保存成功。

组件、记录与统计函数、本地读写放在同一个项目内；不设置 monorepo、共享包、通用服务层或跨平台抽象。使用 React 自带状态管理，不引入全局状态库和后端框架。

本地数据仅属于当前浏览器，清除浏览器数据后会丢失。

## 验证标准

1. 首次进入的空状态能引导用户完成第一条记录。
2. 添加饮水或如厕记录后，明细和今日统计立即一致更新。
3. 撤销后，记录与统计同时恢复到操作前的状态。
4. 刷新后记录仍存在，跨日统计不会混入前一天的记录。
5. 无效饮水量不会产生记录；本地数据读取或保存失败时有可理解的提示。
6. 清空本地数据需要确认，完成后回到空状态。
7. 若展示排行榜，能清楚辨认其为演示数据，不误认为是真实多人排名。

## 下一步

先确定首页信息布局和核心交互，再实现上述最小闭环，通过实际操作验证。以验证结果决定下一次迭代，不提前规划平台和部署路线。
