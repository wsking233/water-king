# 大水之王 · Water King

面向手机触摸操作的饮水与如厕记录原型，通过浏览器访问。纯前端、单机使用，数据保存在当前浏览器，不需要账号或服务端。

## 已实现

- 自定义杯子容量、拖动本杯已喝水量、每次 10 ml 的「嘬一口」、今日累计。
- 嘘嘘计次、今日明细、全部历史、单条撤销。
- localStorage 保存、刷新恢复、按设备本地日期统计、存储异常提示。
- 移动应用布局：固定底部导航、拇指区域记录入口、底部操作弹层。
- 杯子容量预设与自定义、进度回拖修正、点开详情后删除。
- 历史按日期和类型筛选，清空记录前二次确认。
- 适配手机安全区和窄屏；电脑仅展示居中的手机宽度，不提供桌面布局。
- 明确标注模拟数据的排行榜，不上传本地记录。

清除浏览器数据后记录会丢失，不同设备或域名之间不共享记录。2,000 ml 仅用于演示进度，不是医疗建议。

## 本地开发

Node.js 24、npm：

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

## 架构

Vite + React + TypeScript + 普通 CSS。`src/main.tsx` 管理界面和交互，`src/records.ts` 提供数据校验与统计函数，`src/style.css` 提供响应式样式。React 自带状态管理；不引入后端、数据库或跨平台抽象。

## CI/CD：GitHub Actions + GitHub Pages

工作流位于 `.github/workflows/deploy.yml`。每次推送 `main` 或手动运行工作流，依次执行 `npm ci`、`npm test`、TypeScript 检查及 Vite 构建，然后发布构建产物到 Pages。构建或测试失败不会部署。部署只使用 GitHub 自带的短期权限，无需配置个人访问令牌。

首次启用要求：仓库为 Public（私有仓库需要支持 Pages 的付费套餐）；Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。

Pages 地址（以工作流部署成功为准）：https://wsking233.github.io/water-king/

项目按 Pages 子路径 `/water-king/` 构建，无服务端路由。改仓库名时同步修改工作流里的 `--base`。如首次推送发生在 Pages 启用前，在 Actions 中重新运行工作流即可。

## 开发方式

默认直接在 `main` 修改、提交和推送，不创建功能分支或 PR。优先完成可验证的交互闭环；暂不加入云同步、真实多人排行榜或其他平台支持。

## 杯子进度

杯子进度表示本杯「已喝水量」。拖动时预览，松手保存，累计仅计算增量；向回拖动会扣回本杯对应记录。「嘬一口」增加 10 ml，剩余不足 10 ml 时增加剩余量，喝完后按钮禁用。「再接一杯」从零开始，不增加饮水累计；修改容量也会开启新杯，已有饮水记录保留。跨日后本杯从零开始，容量保留。

杯子与记录作为同一个本地数据对象保存，刷新可恢复；写入失败不更改已保存状态。旧版本饮水、嘘嘘记录自动读取，大便记录不再展示或纳入统计。原始旧存储键保留作为迁移来源，新版始终优先使用新存储键。
