## 规则与证据

1. **旧目标**只观察当前真实值：基线 revision、服务器 cutover_at、下一完整北京日 from_day、known 和 goal_ml。不存在目标为 unknown，不补 UI 默认2000；null 是已知关闭。基线不可通过客户端重置。
2. **新在线目标**：打开目标编辑时 `goal_ticket()` 签发按当前用户/云端目标 revision/北京日期绑定的随机凭证。同一用户、版本、日期重取复用，不无限生成。凭证不含可任意回填的日期字段。
3. 只有签发与接收都在同一北京日、且基准版本匹配时，才能确认这一天。新 `sync_goal_apply` 继续调用旧 CAS/receipt 协议；成功 settings receipt 触发不可变日志，使用首次接收时间、实际接受的目标/版本/游标和稳定事件 ID。旧接口 v1 也被 hook 覆盖，不能绕开日志。
4. 同一日以最大服务端 revision 为准。关闭目标延续为已知关闭；后续沿用目标由只读函数计算，无每日填表或 Cron。目标完成只计已知正数且饮水达到目标的记录日。
5. 离线跨午夜、凭证基准不符、旧客户端及旧备份没有可靠日期时，设置仍可正常同步，历史记 unknown。缺口下界取此前最近一次可靠修改北京日，没有则取基线观察北京日。之后在线确认只恢复其当天及以后，不修补更早缺口。
6. 失败 CAS 不消费凭证、不写日志。重复成功 mutation 返回原回执，不挪生效日；重复业务事件 ID 使设置、游标、回执、凭证绑定、日志一起回滚。同一 ID 可用于不同用户，不可用他人的凭证。
7. 若旧缓存页面先经 v1 成功提交了同一个队列 mutation，新页面只确认该成功结果，保留 unknown，不能追加新凭证把旧事实升级为可信历史。已有凭证事件的重试 metadata 必须保持一致。

## 客户端兼容与交互

- 版本 v0.2.2；普通线上版本，无验收分支/参数。
- `Mutation.goalEvidence?={ticket,eventId}` 为现有 outbox 的可选字段，跟随同一笔修改持久化。沿用数据库名/版本/存储键，不清数据，不改变 Store 或备份 v1 格式，不导出凭证。
- 目标编辑显示服务器北京日期；正在取得日期时暂禁保存，失败/离线仍允许保存原私人目标，提示历史覆盖限制。旧本机模式完全不依赖网络。
- 相同目标再次在线保存也产生一笔新确认，可以开始/恢复当天覆盖；有未同步目标或冲突时提示同步后再次确认。
- 冲突选择保留本机时丢弃旧凭证，作为无法证明日期的新 CAS 修改；选择云端不生成目标历史。用户可在同步完成后在线再次保存确认，不冒充过去的离线发生日。
- 目标榜显示本人的历史起日与覆盖不完整提示；旧记录不追溯计分。隐私关闭仍隐藏公开成绩。

## 原子切换和恢复

迁移先设置 `lock_timeout=5s`，按 auth-first 顺序短暂锁住 auth.users 写入，安装实体/回执 hook 后在同事务内捕获当前基线，避免历史无日志窗口。超时/数据约束错误使迁移整体失败，不归一化或删除旧数据。生产只有2个账号，迁移已成功；大规模部署需评估锁时长。

故障时优先恢复旧前端：v1 仍可保存设置，新的 hook 继续记 unknown；不要删除历史来“恢复”。如必须停用新公开 RPC，先撤客户端 EXECUTE；如历史写入阻断私人同步，需受控停用两个 hook 并记录这段覆盖为未知，之后补齐正式恢复方案，不能假装停用窗口仍有证据。保留审计表，不用 DROP CASCADE，不自动重置基线。
