# V0.2 用户与云同步架构及开发任务

状态：WK-01 本地访问层、WK-03 服务端协议与 Worker、WK-04 页面及首次迁移预览已开发；数据库隔离及模拟浏览器流程已验证，真实 Auth/REST 与生命周期待验收。同步预览默认关闭，完整 V0.2 未发布。已实现能力以根目录 README 为准。

## 目标与边界

- 优先完成用户身份、游客云同步、正式账号绑定及多设备恢复；成就、排行榜、宠物均不在本轮。
- 所有私人饮水/嘘嘘记录、每日目标及用户偏好同步至云端；上传不等于公开，默认仅拥有者可读写。
- 每台设备保有独立杯子运行状态（当前杯 ID、水位及设备专属杯容量）；全账号汇总历史饮水事件，绝不把另一设备水位直接套用到本机。
- 维持 React + TypeScript + Vite + GitHub Pages、离线可记录与 JSON 导入导出，迁移前不删除 localStorage。
- Supabase 项目 `water-king` 已创建；产品负责人已完成 Provider、URL Configuration 和 Publishable Key 确认。本次通过 Supabase 工具验证空库并部署私有 profiles 模型；本地公钥配置在不入库的 `.env.local`，Pages 构建仍需同名 Actions Variables。不可在仓库写入 service_role / secret key。

## 组件与数据边界

```text
React 页面
  -> RecordService (本地事务 / 校验 / 待同步队列)
  -> IndexedDB (records, settings, device cup, mutations, sync metadata)
  -> SyncWorker (鉴权 / 上传 / 拉取 / 冲突处理)
  -> Supabase Auth + 受 RLS 保护的 Postgres 表 / 必要 RPC
```

同步之前先建立 Repository 抽象，并保持旧 Store / JSON 备份迁移能力。设备标识存在本机，属于安装实例身份而非登录凭证；浏览器清除网站数据后可能生成新设备。旧 cupId 和 entry.id 应尽可能保留。设备杯状态是否备份到账号需与当前已确认的“每设备独立”兼容：建议按 (user_id, device_id) 隔离备份，只有同一设备实例恢复其杯状态；新设备不自动复制旧杯。

## 建议逻辑数据模型（实际 SQL 以实现为准）

- `profiles`: user_id, nickname, created_at；与 Auth 用户关联。
- `records`: id (UUID), user_id, device_id, kind, amount, at, cup_id?, revision, deleted_at?, updated_at；原有 `id`、`kind`、`amount`、`at`、`cupId` 保持含义。
- `user_settings`: user_id, daily_goal, preferences, revision, updated_at；目标历史生效规则在排行榜开发前明确。
- `device_cups`: user_id, device_id, cup_id, capacity, revision, updated_at；当前杯消耗进度可由杯关联的饮水记录推导，避免写两个互相矛盾的真相源。
- `processed_mutations` / `change_log`（或等价 RPC）：请求去重、单调服务端游标、增量下发删除标记。
- 游客最近有效活动、绑定与过期处理基于服务端认证状态及服务端时间；30 天规则沿用 `USER_SYSTEM.md`，不可将本机记录一起删除。

云端对每张私有表启用 RLS，基于 `auth.uid()` 校验归属；新建时 `user_id` 不能由客户端冒充其他账号。角色为 authenticated 不等于“已绑定用户”：匿名游客也可能属于这个角色。客户端仅使用公开可发布密钥及当前用户凭证。管理员密钥和清理逻辑只存在服务端。排行榜未来使用独立、最小化聚合接口，不直连私人嘘嘘数据。

## 同步约束

1. 先成功提交本地事务，再反馈记录成功；联网状态只影响云同步状态。
2. 本地记录操作与 `mutationId` 同事务入队；断网、后台返回和重试不会丢队列。
3. 服务端幂等处理 `mutationId`，并通过 `recordId + revision` 检测冲突；不能单纯以客户端时间戳决定覆盖。
4. 删除保留墓碑直到所有有效增量客户端能获知删除；服务端游标须单调，分页与快照一致性在实施时测试。
5. 同账号不同设备新增独立合并；同一记录并发编辑、编辑与删除竞态需显式处理，未解决冲突保留本地改动并提示，不能静默覆盖。
6. 首次云同步显示本机导入/合并范围，按稳定 ID 去重；相同时间与水量并不等于同一条记录。
7. 登录、登出、账户切换必须隔离 IndexedDB 用户命名空间和未发出的队列，禁止旧账号记录串入新账号。
8. 未绑定游客身份过期后保留本机数据；需明确重新建立账号及重新上传的确认流程，不可凭旧 userId 直接恢复身份。
9. `device_cups` 不随其他设备的记录拉取更新其自身水位；同设备操作仍遵守容量、加满、撤销和编辑约束。
10. 同步完成仅指服务器确认已应用且同步游标更新成功；断网显示待同步而非伪称成功。
