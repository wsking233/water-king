# 用户系统：游客优先

状态：设计规格，尚未实现。决策状态见 [产品规格入口](README.md)。

## 已确认要求（产品负责人提出）

| 编号 | 规则 |
| --- | --- |
| US-01 | 默认无需注册。用户可选择游客登录，不填写密码；系统自动生成用户 ID，允许修改用户名（昵称）。 |
| US-02 | 浏览器保留游客身份，后续默认自动登录。清除身份数据或更换设备、浏览器后不能识别原游客，需要登录已绑定账号或创建新游客账号。不能按昵称找回游客。 |
| US-03 | 用户后续可选关联邮箱、手机号等登录信息，并可在此时设置密码，持续保留身份和数据。绑定不能成为首次体验或游客同步的前提。 |
| US-04 | 游客记录正常上传。游客是有服务端身份的用户，不是“仅本地、不允许同步”的试用模式。 |
| US-05 | 连续 30 天未登录的未绑定游客，其云端账号及关联信息自动删除。此规则不适用于已绑定账号。 |

“清缓存会丢身份”的准确含义是清除 Cookie／网站数据或匿名凭证丢失；只清静态资源缓存不一定退出登录。不能承诺未绑定游客在凭证丢失后可恢复。

## 配套设计基线

### US-06 身份标识与认证分离

用户 ID 用于标识，不是密码或登录凭证。服务端创建匿名账号并签发不可猜测、可撤销的认证凭证，浏览器按选定认证方案安全持有，之后自动恢复会话。不能接受“提交任意 userId 就登录”，不能把凭证写入日志、公开 URL 或备份文件。后续确定服务架构后选择具体会话方案，不在本规格绑定供应商或存储实现。

昵称是展示字段，可以重复，不是登录名。无需首次填表即可提供默认昵称并开始记录；允许稍后修改。长度、字符限制及频率待定。

### US-07 绑定是原账号升级

验证邮箱或手机号的所有权后，在当前账号上增加登录方式，保留同一用户 ID、记录、成就、宠物与榜单关联。不能要求重新注册并丢弃游客数据。验证未完成仍按游客处理；成功绑定后才退出游客清理范围。

产品负责人已要求绑定阶段可设置密码，不能擅自删掉该能力。邮箱验证码免密登录、首版只开放邮箱属于待决选项，不替代密码需求。提供密码登录时同步设计修改密码和找回密码；从未绑定的游客不能通过猜测 ID 或昵称找回。

### US-08 30 天活跃与删除

建议将“登录”落实为用户正常使用时的成功认证访问或有效同步；自动恢复会话也算登录，不要求重复点击按钮。由服务端时间维护 `lastActiveAt`，不能信任客户端自行传入的活跃时间，也不能靠无意义后台心跳永久续期。

未绑定且达到连续 30×24 小时未活跃时失去恢复旧身份的资格，清理任务删除在线账号、记录、榜单关联、成就与宠物等关联信息，旧凭证失效。具体物理清理任务频率及备份副本保留策略需在服务方案中明确，不宣称所有备份会在到点瞬间消失。

即使定时任务尚未运行，过期账号也不能靠重新访问复活。清理与绑定、同步并发时必须原子判断资格，不能删除已成功绑定或在到期前有效活跃的账号。绑定完成后按已绑定账号策略处理，不能继续套用游客期限。

### US-09 离线与账号过期

已有离线应用可以先本地记录；没有网络时不强行创建远程游客，不虚报上传成功。首次在线使用提供简短的游客上传与保留说明，通过“直接开始”等明确动作进入游客模式，不要求填写密码。

云端清理不主动清空设备本地记录。超过期限后联网，明确提示原游客已过期；允许创建新游客并确认是否上传保留的本机记录。新账号获得新 ID，不恢复旧线上身份、排名或奖励。未确认前不丢弃本地数据、不把它们归给其他账号。

### US-10 数据上传、公开与归属

游客与绑定用户使用同一套记录上传能力。离线队列、重试去重、修改和删除同步、冲突处理必须一致，不能只上传新增记录而忽略删除。

上传不等于公开；排行榜另行控制参与和公开字段。每条数据归属认证用户，服务端验证访问权限，不信任客户端指定的任意用户 ID。

用户说“游客记录正常上传”；2026-10-16 已确认：饮水和嘘嘘全部私人记录及用户设置都进入云同步；默认不公开，仅对应认证用户可访问。杯子的当前状态按设备独立，历史饮水事件归用户合并统计，不能跨设备覆盖当前杯水位。

### US-11 已有绑定、切换与合并

若邮箱或手机号已属于另一账号，不能直接把游客数据覆盖到该账号。先验证并登录目标账号，再展示迁移/合并范围供用户确认。饮水记录依据稳定 ID 去重；相同时间与水量不必然是重复记录。

成就、排行榜和宠物奖励不简单相加，不因合并或重试重复发放；具体规则分别在系统规格中确定。退出与切换账号需隔离本地数据和待同步队列，不能把前一用户的数据上传给后一用户。尚未上传的记录提供保留或导出路径，不静默删除。

### US-12 低打扰提示与基本保护

“我的”显示游客身份、同步状态和绑定入口；不以反复弹窗阻断记录。提示示例：

> 当前为游客。清除网站数据或更换设备后，无法找回此账号。绑定登录方式可跨设备使用；未绑定游客连续 30 天未联网使用，云端账号及数据将被清理。

只有同步确实完成时才显示“记录已同步”。服务端做基础匿名创建限流、接口访问控制及记录校验；不要为早期游客体验引入复杂注册验证或大型风控系统。

## 状态与恢复行为

| 状态 / 事件 | 预期行为 |
| --- | --- |
| 本地使用且尚无云端身份 | 可继续记录；联网选择游客后建立身份并处理本机记录上传 |
| 有效游客凭证仍在 | 自动恢复同一账号，修改昵称不更换 ID |
| 凭证丢失且未绑定 | 新建游客；不能凭 ID 找回旧游客，旧账号仍按原活跃时间清理 |
| 游客绑定并验证成功 | 原 ID 升级，退出游客清理范围 |
| 已绑定账号换设备 | 使用已绑定方式登录并恢复允许同步的数据 |
| 30 天过期后携带旧凭证返回 | 拒绝恢复旧身份，保留本机记录，提示创建新游客或登录 |
| 网络失败 | 本地记录继续，显示待同步，不当作凭证失效而不断创建游客 |

## 实现前待决事项

1. 首版支持邮箱、手机号中的哪些渠道；密码登录入口和验证码登录是否同时支持。
2. 昵称默认值、长度、修改频率；头像是否仅预设。
3. 已确认：全部私人记录及设置同步；杯子当前状态按设备独立。仍需细化设备杯容量与默认设置关系、同步告知文案。
4. 同时修改同一条记录的冲突策略；设备杯状态的本地与云端恢复、设备 ID 丢失后的处理。
5. 清理任务执行频率、清理前是否提醒、备份与必要日志的保留方式。
6. 已有账号合并的成就、宠物和榜单处理规则。
7. 认证及服务供应商、费用、账号主动删除流程。

## 验收场景

- 无邮箱、手机号和密码即可游客使用；改名后 ID 不变，刷新后仍为原账号。
- 仅知道他人的 ID 无法登录或访问数据；不同账号数据相互隔离。
- 游客新增、编辑、删除可同步；重试不重复创建记录或匿名账号。
- 绑定验证成功保留原数据；失败不丢数据；已被绑定的信息不覆盖其他账号。
- 服务端时钟边界测试到期前、恰好 30 天、到期后；后台无效心跳不续期。
- 清理与绑定、同步并发不误删有效账号；已绑定账号不被游客任务删除。
- 过期凭证不能复活账号；本机数据保留，新账号上传需确认。
- 离线、清网站数据、换浏览器、切账号、上传中断及合并重试行为符合上述规则。
