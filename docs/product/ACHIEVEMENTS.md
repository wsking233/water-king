# 成就首版规格（AC-01，已确认）

产品负责人本轮明确要求开始开发，并确认下列九项门槛、**按当前有效记录重算，可收回**、首版仅云端（游客/邮箱同等），只展示徽章，无积分或宠物奖励。v0.3.0 实现；真实 iPhone 验收仍待完成。

## AC-01 清单与口径

| 稳定 ID | 展示名 | 指标与门槛 |
| --- | --- | --- |
| first_record | 初次记录 | 至少1条服务端有效饮水或嘘嘘记录 |
| record_days_3 | 三天记录 | 累计3个有效北京记录日 |
| record_days_7 | 一周积累 | 累计7个有效北京记录日 |
| record_days_30 | 三十天记录 | 累计30个有效北京记录日 |
| streak_3 | 连续三天 | 历史最长连续有效记录日达到3天 |
| streak_7 | 连续一周 | 历史最长连续有效记录日达到7天 |
| goal_days_3 | 目标起步 | 可靠历史目标完成3天 |
| goal_days_7 | 七日目标 | 可靠历史目标完成7天 |
| goal_days_30 | 三十日目标 | 可靠历史目标完成30天 |

连续类按当前有效历史的最长连续记录段，不是排行榜“今天/昨天起算的当前连续”。历史目标复用 v0.2.2 可靠基线/事件，未知日期与关闭目标不计数。有效日为饮水或嘘嘘；同日多次只算一天，统一 Asia/Shanghai。旧记录、补记、导入经服务端接受后均参与当前条件判断，稳定 ID / mutation 重试不重复计量。

不读杯子剩余量，不按喝水总量或嘘嘘次数发奖励，不诱导多喝、不要求勉强达成目标。

## AC-02 状态可撤回

不是永久纪念，不建立不可撤回的“已解锁”账本。服务器从当前有效事实按需计算：达到条件即当前达成；删除、编辑、记录时间移动、目标历史出现未知缺口，都可能收回；恢复或补记重新满足条件则再次达成。不虚构首次解锁日期，界面只显示本次服务器确认时间。

规则固定 v1；未来修改门槛/清单须升级规则版本并明确客户端兼容，不能悄悄改变条件。

## AC-03 账号、私有和离线

只对云端账号提供，游客和邮箱同等；默认私有，不随排行榜公开。纯本机提示接入同步后确认，未同步改动不宣称达成。绑定保留用户 ID。恢复备份只恢复记录，不接受客户端传入“成就已解锁”，由服务器重新计算；不做账号合并或领取接口。

断网显示本账号上次服务器结果，明确标注缓存与时间；联网刷新重新确认，旧缓存不作为服务器依据。账号变化立即清空当前展示，缓存按账号隔离。本机资料与备份存储键保持兼容。退出排行榜不影响私有成就。

服务端不新增奖励/解锁表，因此真实账号删除或游客清理无成就表孤儿；来源记录与目标历史沿用既有生命周期。未安排 Cron 或真实删除任务。

## AC-04 交互与验收

「我的 → 我的成就」底部弹层，不增加第六个导航项。九枚徽章、达成数量、进度、条件、服务器时间、历史目标不足、待同步、加载/错误重试/离线提示；不播放打断记水的庆祝动画。

验收覆盖：首条记录、同日去重、北京跨日、历史最长连续/断档/补记、旧记录补发当前条件、目标关闭/未知缺口、删改收回与恢复；匿名/跨账号拒绝、不能客户端自报分数/状态；320px、错误重试、离线缓存及恢复、更新数据保留。生产接口与测试证据见 [ACHIEVEMENTS.md](../architecture/ACHIEVEMENTS.md)。
