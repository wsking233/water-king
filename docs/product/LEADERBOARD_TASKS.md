## LB-02 服务端数据与计算（待开发）
1. 分析 `sync_entities` 设置单一当前值及历史备份格式，提出目标历史不可逆缺口的兼容方案；先做设计与可重放的 SQL fixture。
2. 为排行榜构建私有可计算事实层和安全的目标变更历史；保留当日最后有效目标、生效北京日期、禁用状态、服务端认证；旧记录不能伪造历史目标。
3. 用户参与设置及公开投影：游客与邮箱账号均默认加入，无记录账号也参加，关闭立即从公开结果排除；公开字段最小化；处理用户/游客身份生命周期。
4. 五榜计算函数、午夜边界、跨日连签、重试幂等和删改回算；采用服务端确认值，避免重复上传计分。
5. 支持并列名次、零数据邮箱绑定者优先的稳定排序、20 条有界分页、“我的排名”、数据刷新时间和空榜。
6. PGlite/SQL 回归：跨账号越权、非登录查询边界、恶意参数、游客默认参加、零分/同分、19/20/21/41 条、无数据邮箱优先、重复变更、跨零点、历史缺口。
7. 生产迁移单独提交待用户批准；本阶段不得擅自 apply migration。

**退出**：服务端测试完整、公开接口无隐私泄漏、迁移可审计且未越权部署。

## LB-03 客户端（待开发）
1. 导航增加排行榜，五项独立切换，小于等于 20 人全部展示、超过 20 人前 20 与按 20 加载更多。
2. 我的名次独立显示；未参加时明确提示；零成绩用户也展示在真实榜单末尾，不伪造占位用户。
3. “我的 → 排行榜隐私”默认参与并支持即时退出；提示昵称和聚合成绩将公开。
4. 等待同步、离线缓存、榜单时间、错误重试和下拉刷新/刷新入口。
5. 320px 和 iPhone Safari 手势、安全区、长昵称、分页加载测试。

**退出**：无好友/积分/宠物入口干扰，断网不显示“实时”；私有记录未通过榜单 API 下发。

## 任务切分建议
- Codex A：目标历史模型设计 + SQL fixture（不要与线上同步协议直接混写）。
- Codex B：榜单聚合 SQL、公开查询权限及回归（依赖 A 的数据契约）。
- Codex C：React 界面与 mock API 浏览器测试（可在 A/B 期间基于冻结的契约进行）。
- 主线集成：一个提交一批次；先设计评审，再迁移审批，最后真实联调。仓库当前默认直接 main 工作；并行 Agent 需遵循 agent.md 文件锁与协调要求。

## 技术特别注意
- 当前系统的水杯状态按设备独立，排行榜只处理已同步记录；不直接读 localStorage 或客户端缓存计分。
- 参加排行榜本质上是公开资料的行为。账号删除、游客过期需同步清理投影；关闭参与应立即不可查询，缓存过期与重新打开明确处理。
- 今日榜在 Asia/Shanghai 日界更新，不能靠写入事件触发才刷新。
- 昵称可相同，UI 排序内部稳定键不得泄露帐号 UUID。
